# מה זה Hermes, ואיך הוא עובד אצלנו

## במשפט אחד
**Hermes Agent** הוא סוכן AI בקוד פתוח של Nous Research שרץ אצלנו on-prem. זה תהליך אחד שמחזיק "עובד" עם זהות, ידע מקצועי, כלים, זיכרון ולוח זמנים. אפשר לדבר איתו ב-Slack, בצ'אט באפליקציה ובטרמינל, והוא גם עובד לבד לפי שעון.

**Hermes הוא לא המודל.** המודל (אצלנו Kimi K3) הוא ה"מוח" שמנסח ומחליט. Hermes הוא ה"גוף": הוא מחבר את המודל לכלים, לזיכרון, לערוצים ולמשימות מתוזמנות, ושומר על הגבולות.

## ממה הוא בנוי
| רכיב | מה זה | אצלנו |
|---|---|---|
| **פרופיל** | סביבה מבודדת עם תיקייה משלה (`HERMES_HOME`): זהות, הגדרות, זיכרון, היסטוריה, משימות | `noc-engineer` |
| **SOUL.md** | ה"אישיות" והכללים. נטען לכל שיחה | מהנדס NOC שמאתר איפה התקלה, קריאה בלבד |
| **Skills** | קבצי ידע ונהלים (`SKILL.md`). נטענים רק כשרלוונטי | 18: מסלולי עבודה, תחומים ושכבות |
| **MCP** | הפרוטוקול שדרכו הוא מפעיל כלים חיצוניים | ה-FastMCP שלך: Prometheus, Kafka, Jira, חוקים ועוד |
| **מודל** | ה-LLM שמאחוריו, דרך API תואם OpenAI | Kimi K3 (`provider: custom`) |
| **זיכרון** | מה שהוא לומד לאורך זמן (`memories/`) | ידע על הסביבה. לא מסד נתונים תפעולי |
| **Gateway** | התהליך שרץ תמיד ומחבר את הערוצים | Slack, API לאפליקציה ו-cron, בתהליך אחד |
| **Cron** | משימות מתוזמנות, עם LLM או בלי | דוח בוקר, סקירה יזומה כל 15 דקות, 5 סקריפטים |

## איך שיחה עובדת
1. משתמש כותב ב-Slack או באפליקציה.
2. ה-Gateway מקבל את ההודעה ופותח או ממשיך סשן.
3. Hermes בונה את ההנחיה: SOUL, הזיכרון הרלוונטי, רשימת ה-skills והכלים המותרים (`tools.include`).
4. המודל מחליט: לטעון skill, להפעיל כלי MCP, לחשוב שוב. הלולאה חוזרת עד שיש תשובה.
5. התשובה חוזרת לאותו ערוץ, וכל צעד נרשם בהיסטוריית הסשן.

## איך משתמשים פותחים איתו שיחה
| ערוץ | למי | איך |
|---|---|---|
| **Slack** | כל הצוות | מתייגים את הבוט בערוץ הצוות או שולחים לו הודעה פרטית. כל thread הוא שיחה נפרדת. רק מי שמופיע ב-`SLACK_ALLOWED_USERS` מקבל תשובה |
| **האפליקציה שלך** | משתמשי ה-UI | רכיב צ'אט (`examples/web-app/NocAgentChat.tsx`) שקורא ל-backend שלך (`hermes_proxy.py`), שקורא ל-Hermes ב-`/v1/chat/completions` (פורט 8642). המפתח נשאר בשרת |
| **Open WebUI / LibreChat** | אופציונלי | מחברים כ-endpoint תואם OpenAI עם `API_SERVER_KEY`, ו-Hermes מופיע כמודל `noc-engineer` |
| **טרמינל** | מנהל ובדיקות | `hermes -p noc-engineer chat` |

דוח הבוקר והתראות הסקירה היזומה נשלחים לערוץ ה-Slack שמוגדר ב-`SLACK_HOME_CHANNEL`.

## מה Hermes דורש כדי לרוץ
| מה | איפה מגדירים | מי ממלא |
|---|---|---|
| כתובת המודל ושם המודל | `config.yaml` → `model.base_url`, `model.default` | אתה |
| מפתח המודל | `.env` → `OPENAI_API_KEY` | אתה (Secret) |
| שרת MCP ורשימת כלים | `config.yaml` → `mcp_servers.noc_mcp` | אתה |
| API לאפליקציה | `config.yaml` → `gateway.api_server`, ו-`API_SERVER_KEY` ב-`.env` | ✅ מוגדר, צריך רק מפתח |
| Slack | `SLACK_BOT_TOKEN` (xoxb), `SLACK_APP_TOKEN` (xapp), `SLACK_ALLOWED_USERS`, `SLACK_HOME_CHANNEL` | אתה. את ה-app ב-Slack יוצרים עם Socket Mode |
| אחסון קבוע | PVC ל-`HERMES_HOME` | אתה: storage class ונתיב ב-image |
| תהליך רץ | `hermes -p noc-engineer gateway run`, עותק אחד בלבד | ✅ ב-`deployment/k8s/hermes.yaml` |

## גבולות חשובים
- **עותק אחד בלבד.** שני עותקים יריצו כל cron פעמיים, ו-Slack מאפשר חיבור אחד לכל token.
- **ההרשאות נאכפות ב-MCP, לא ב-SOUL.** ה-SOUL הוא בקשה מהמודל. המניעה האמיתית היא שכלי כתיבה מסוכנים פשוט לא קיימים.
- **כל המשתמשים מקבלים את אותם כלים.** הרשאה לפי משתמש אפשרית רק בשכבת ה-MCP או ב-backend של האפליקציה.
- **הזיכרון משותף לפרופיל.** לא שומרים בו מידע אישי או פרטי לקוחות.
- **את `config.yaml` החי משנים** עם `hermes config set`, לא בעריכה ידנית.
